If RStudio can't find TensorFlow, the fix is not deleting your PC. Three commands, done forever.

🖥️  One ofLinux, macOS, or Windows 11 (via WSL2, see below)

Curious why this keeps breaking? (optional read)

RStudio is just the IDE. The language inside it is R. But TensorFlow has no native R implementation — instead there is an R package, also called tensorflow (and keras), which is a thin wrapper that calls the Python TensorFlow library through a bridge package named reticulate.

So when you type library(tensorflow) in RStudio, this happens:

R (library(tensorflow))  →  reticulate  →  some Python interpreter  →  TensorFlow

The fragile link is "some Python interpreter". Reticulate has to find and pick one — a system Python, a conda env, a venv, a half-uninstalled Anaconda... If it picks one without TensorFlow installed, you get exactly the wall of errors you've been staring at. Reinstalling RStudio or wiping the machine doesn't fix it, because the next Python it finds can be wrong again in the same way.

The fix: stop letting R guess. Pin one Python, with TensorFlow in it, and hard-wire R to it via an environment variable. That's what this project's Nix flake does — and it also pins R, RStudio, and every package, so the setup is reproducible from zero.

The setup (Linux and macOS)

1
Install Nix (one-time, ~5 min). The Determinate installer is the friendliest option: 
curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
Close and reopen your terminal afterwards.

Already have Nix? You only need flakes enabled (Determinate enables them by default).

2
Run the one command: 
nix run github:YOURNAME/rstudiowithtensorflow

Now walk away for a while. The first run downloads R, RStudio, and Python (~4 GB) and may compile some things — anywhere from 10 minutes to an hour depending on your machine and internet. That's normal and happens exactly once. RStudio then opens by itself, already wired to the right Python and TensorFlow.

3
Verify in RStudio's console (bottom-left pane): 
library(tensorflow)
tf_config()

You should see the TensorFlow version and the Python it found — pointing inside your user cache folder. Done.

Next time: same command, opens in seconds. Prefer hacking in a terminal? git clone the repo, cd in, nix develop, rstudio — also gives you Rscript.

Windows 11 users

One extra step first: put a real Linux inside Windows (WSL2), then follow the steps above from inside it. RStudio's window opens normally.

wsl --install   # PowerShell as Administrator, then reboot
# an Ubuntu terminal opens — in it:
curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
# close & reopen the Ubuntu app, then continue with step 2 above

It didn't work?

SymptomFix
nix develop errors on an R package failing to build Use nix develop .#minimal instead. Then inside R: install.packages(c("tensorflow","keras3")).
RStudio opens but tf_config() finds no TensorFlow You opened a regular RStudio from your app menu. Launch it with nix run github:YOURNAME/rstudiowithtensorflow.
Anything else weird Clean slate: rm -rf ~/.cache/rstudiowithtensorflow, rerun the command. Still stuck? open an issue.
How it works under the hood (optional read)

One Nix flake pins the whole stack. TensorFlow itself comes from official PyPI wheels (nixpkgs' Python TensorFlow build is broken upstream), everything else comes from the Nix binary cache:

PieceSourceWiring
RStudio, wrapped with the R packagesNix (rstudioWrapper)R_PROFILE
R + reticulate + tensorflow/keras3 glueNix (rWrapper)RSTUDIO_WHICH_R
Python interpreterNixbase of .venv
TensorFlow, numpy, pandasPyPI wheels via uvRETICULATE_PYTHON

On first run, a uv venv is created in your user cache (~/.cache/rstudiowithtensorflow/venv) and RETICULATE_PYTHON is exported pointing at it — after that, reticulate has exactly one Python to pick, and it's the right one. Always.

If R ever warns about a TensorFlow version mismatch: edit requirements.txt to the exact version it asks for, rm -rf ~/.cache/rstudiowithtensorflow, rerun the command.
